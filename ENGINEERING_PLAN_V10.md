# Live Presenter v10 — Oracle Distillation Engineering Plan

## Objective

Move Live Presenter from hand-authored representation heuristics toward an empirical editorial policy learned from human/offline-editor behavior **without** giving a learned model authority to bypass grounding, provenance, visual grammar, or intervention safety.

The system should learn answers to a narrow question:

> Given the discourse function, stage state, and available evidence/assets, which representation is most useful *now*, and what should be prepared before it is needed?

This is not a plan to turn the runtime into an offline video editor. Offline editors are supervision/oracle producers. The live path remains the low-latency Chromium object stage.

---

## Architectural invariant

The authority chain remains:

1. semantic state / current concept;
2. discourse-act inference;
3. grounding and evidence availability;
4. deterministic visual grammar;
5. intervention policy / stage lock;
6. **oracle-distilled representation policy as adviser**;
7. provider preparation and stage rendering.

V10 is **shadow mode**. The learned policy can rank representations and warm providers. It cannot turn a HOLD/WITHHOLD into SHOW and cannot replace a grounded broker result merely because the empirical policy disagrees.

---

## Workstreams

### A. Oracle acquisition

Create a corpus of explanatory talks and multiple editorial traces per talk.

Target progression:

- pipeline verification: synthetic fixture only;
- first empirical tranche: 30 non-fixture talks / >=150 consensus events;
- useful research tranche: 60–100 talks / >=400–800 events;
- activation candidate: >=100 talks / >=500 events with >=100 held-out events.

For each talk retain:

- stable `talk_id`;
- timed transcript or transcript segments;
- editor identity/version;
- normalized editorial interventions;
- source URI and rights basis/license;
- domain/language/style metadata;
- availability context: dataset, images, sources, graph, map, dated-event timeline;
- hashes of the source trace bundle.

Do **not** mix events from one talk across train and eval.

### B. Editor ensemble

Use at least two independent traces for useful consensus. Preferred first ensemble:

- one human/hand-reviewed trace when feasible;
- AutoBroll-style planner output;
- Video-Alchemy-style or another independent timeline planner;
- optional additional editor/model.

The point of multiple editors is not majority voting as truth. Consensus provides a transparent high-confidence baseline; disagreements remain valuable training/evaluation records.

Avoid a false ensemble where multiple traces are generated by the same model/prompt family with superficial parameter changes. Record model/editor versions in the manifest.

### C. Normalization contract

All editor outputs normalize to the v9 `EditorialEvent` contract:

- start/end;
- discourse function;
- representation;
- placement;
- retrieval query;
- rationale;
- transcript source;
- alternatives;
- asset URI;
- provenance/editor/version;
- confidence and metadata.

V10 adds an `OracleExample` layer binding consensus events to transcript text and runtime availability context.

### D. Dataset construction

`oracle_dataset_v10.py` now performs:

- bundle loading;
- v9 adapter normalization;
- transparent multi-editor consensus;
- transcript alignment;
- availability-context normalization;
- talk-level deterministic splitting;
- dataset statistics and warnings.

The canonical generated artifact is:

`artifacts/v10/oracle_dataset_v10.json`

### E. Representation policy

The first learned policy is intentionally interpretable rather than neural.

`representation_policy_v10.py` learns confidence-weighted categorical counts with:

- per-function distributions;
- function+availability-context distributions;
- global-prior smoothing;
- feasibility filtering;
- minimum support;
- confidence threshold;
- entropy-based abstention;
- hierarchical backoff.

This is the right first model because it lets us determine whether the corpus contains a stable editorial signal before adding model complexity.

Possible later upgrade only after real data exists:

- pairwise ranking model over candidate scenes;
- calibrated multinomial logistic model;
- small tree/GBDT ranker;
- learned timing/prefetch hazard model;
- sequence model for editorial event timing.

A larger model should only replace the count policy if held-out performance and calibration materially improve.

### F. Live integration

`runtime_v10.py` runs the oracle policy in shadow mode.

It currently:

- computes runtime availability context;
- records a recommendation for the inferred discourse act;
- records disagreements with the safe semantic broker;
- can ask the v9 provider registry to warm a likely scene for `relate` / `explain`;
- stores a warmed provider scene in the existing representation cache;
- exposes the full state under `snapshot()["v10"]`;
- cannot bypass grammar or grounding;
- cannot autonomously escalate to SHOW.

This is the first live learning seam.

### G. Governance and provenance

`oracle_manifest_v10.py` hashes every bundle and records:

- talk ID;
- file hash;
- fixture status;
- source URI;
- license/rights basis;
- domain/language;
- editor name, shape, version.

Non-fixture corpora should run the manifest builder with `--strict-rights` before entering training.

`oracle_bundle_schema_v10.json` documents the portable ingestion contract.

### H. Promotion gates

`policy_gate_v10.py` prevents synthetic or tiny-corpus success from being mistaken for readiness.

Current thresholds:

#### Shadow

No minimum empirical corpus. Recommendation is observability only.

#### Canary

- >=30 talks;
- >=150 examples;
- >=40 held-out examples;
- >=0.65 policy coverage;
- >=0.75 selective accuracy;
- >=30 non-fixture talks;
- successful browser rehearsal evidence.

Canary still should not create ungrounded scenes. The first canary authority should be limited to **choosing among already-ready, grammar-valid candidate scenes**.

#### Active

- >=100 talks;
- >=500 examples;
- >=100 held-out examples;
- >=0.80 coverage;
- >=0.82 selective accuracy;
- >=100 non-fixture talks;
- browser rehearsal pass;
- no unresolved dataset warnings.

Before active authority, also add live timing/oracle-gap gates and repeated browser robustness runs.

## Phased engineering schedule

### P0 — contracts and shadow skeleton — implemented in v10

Deliverables:

- bundle schema;
- provenance manifest;
- leak-resistant dataset builder;
- transparent learned policy;
- offline evaluation;
- runtime shadow integration;
- provider warming;
- promotion gate;
- Chromium rehearsal;
- full regression suite.

Exit condition: v1–v10 tests pass and Chromium rehearsal has no grammar regression.

### P1 — real acquisition runners

Build adapter runners that consume outputs from chosen offline editors and produce a complete `oracle_bundle_schema_v10.json` bundle.

Deliverables:

- AutoBroll runner/importer;
- Video-Alchemy runner/importer;
- generic JSON/CSV human edit importer;
- timed transcript import (SRT/VTT/JSON);
- editor/version pinning;
- source/rights capture;
- acquisition failure/retry log.

Exit condition: a single command can create a valid bundle from one real talk and at least two editor traces.

### P2 — first 30-talk empirical corpus

Sample across at least these strata:

- technical/software explanation;
- science/engineering;
- finance/economics;
- policy/social science;
- data-heavy presentations;
- concept-heavy / low-data explanations.

Within strata, vary:

- speaker pace;
- slide density if a source deck exists;
- narration style;
- talk duration;
- availability of charts/images/data.

Exit condition: 30 rights-clean non-fixture talks, >=150 consensus editorial events, at least two independent editor traces each.

### P3 — disagreement review

Build a compact review surface for events where editors disagree strongly.

The reviewer sees:

- local transcript window;
- each editor proposal;
- timing offsets;
- function and representation labels;
- asset/source provenance;
- current consensus result.

Actions:

- accept one;
- merge compatible proposals;
- relabel function/representation;
- mark "no visual";
- flag bad source/asset;
- flag ambiguous discourse.

The review output must be a **new trace**, not silent mutation of the original editor data.

### P4 — empirical policy v2

Compare three models under talk-isolated holdout:

1. count/backoff baseline (current v10);
2. calibrated multinomial model;
3. pairwise candidate ranker.

Report:

- top-1 representation accuracy;
- top-k accuracy;
- coverage;
- selective accuracy;
- log loss/calibration;
- confusion by discourse function;
- per-domain slice;
- per-availability-context slice;
- abstention quality.

Choose the smallest model that materially beats the baseline without harming calibration or abstention.

### P5 — timing and prefetch model

Representation choice and *when to prepare* are separate problems.

Build a hazard/ranking model for:

- probability of an editorial event within next N seconds;
- likely representation family;
- expected preparation latency;
- expected speculative waste.

Optimize something like:

`expected usefulness * probability_needed - latency_cost - speculative_waste_cost - transition_churn_cost`

Evaluate against the v9 oracle-gap benchmark.

Key comparison conditions:

1. reactive only;
2. recent-speech proactive;
3. semantic-trajectory proactive;
4. oracle-distilled trajectory proactive;
5. offline full-future oracle.

### P6 — canary authority

Only after the gate passes, allow the learned policy to choose among **already-prepared candidates**.

Canary selection must require:

- same active concept;
- candidate scene passes visual grammar;
- grounding ledger allows it;
- no stage lock;
- oracle policy not abstaining;
- recommendation confidence/support above threshold;
- intervention policy independently says SHOW.

The learner still cannot invent an ungrounded scene or force a topic transition.

### P7 — live rehearsal study

Run scripted and unscripted held-out rehearsals:

- degraded network;
- fast/slow speech;
- skipped planned branches;
- sudden off-graph tangent;
- repeated backtracking;
- presenter correction;
- audience question;
- show-sources / back / hold / resume.

Capture:

- stage trace;
- wall-clock latency;
- semantic state;
- oracle recommendation;
- broker selection;
- prefetch work;
- presenter correction/recovery;
- audience-facing object history.

Human preference/comprehension remains a separate later validation, not a prerequisite to engineering robustness.

### P8 — production hardening

After empirical value is established:

- persistent model/artifact versioning;
- deterministic replay;
- fallback when policy file is corrupt or missing;
- provider failure isolation;
- performance budgets;
- cache eviction policy;
- rights/provenance auditability;
- runtime health endpoint;
- canary kill switch;
- reproducible benchmark package.

## Data quality risks

### Correlated oracle bias

If every editor is effectively the same model family, apparent consensus is meaningless.

Mitigation: retain editor family/version and deliberately include heterogeneity.

### Availability confounding

Editors choose what they can generate/retrieve. A policy trained without context could learn "always media" because the oracle had unlimited media while the live runtime did not.

Mitigation: availability context is a model input and evaluation slice.

### Timing mismatch

An offline editor knows future speech. A live runtime does not.

Mitigation: preserve event timing and causal availability. The v9 oracle benchmark should explicitly score what was knowable at event time.

### Domain leakage

A random event split leaks talk style, vocabulary, speaker and topic into both sides.

Mitigation: talk-level split now; domain-level holdouts later.

### Copyright/rights

Public availability is not permission to build/distribute a derived dataset.

Mitigation: strict rights manifest and source-specific review before empirical acquisition.

### Synthetic overconfidence

The bundled fixture is deliberately learnable. High synthetic accuracy is expected.

Mitigation: promotion gate requires non-fixture talks; synthetic performance is engineering evidence only.

---

## Immediate next tranche

1. Choose the first real 30-talk corpus with explicit rights basis.
2. Generate at least two independent editor traces per talk.
3. Normalize them into the v10 bundle contract.
4. Hash/manifest before training.
5. Train the count baseline.
6. Inspect distributions and disagreements.
7. Evaluate on held-out talks.
8. Run the resulting policy in shadow mode against unrelated rehearsals.
9. Compare runtime choices against held-out editorial oracle.
10. Only then consider model upgrade or canary authority.

This keeps the project bounded: the next work should answer whether empirical editorial supervision improves the live semantic stage, not simply add more features.
